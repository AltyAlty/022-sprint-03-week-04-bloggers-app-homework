1. Backend‑фреймворк Express.js - это backend‑фреймворк для Node.js, предназначенный для создания серверных приложений,
RESTful API, маршрутизации и работы с middleware.

2. Тестовый фреймворк Jest - это тестовый фреймворк для тестирования кода JavaScript. Используется для написания и
выполнения различных видов тестов, тестовых утилит и моков.

3. Трансформер TS-Jest - это трансформер для тестового фреймворка Jest, позволяющий тестировать код TypeScript путем
компиляции и выполнении его во время тестирования.

4. Библиотека Supertest - это библиотека для e2e-тестирования HTTP-запросов. Используется для тестирования API,
отправляя запросы к серверу и проверяя ответы.

5. Линтер ESLint - это инструмент статического анализа кода для JavaScript и TypeScript. Используется для анализа кода
на наличие ошибок и проблем с качеством, таких как несоответствие стилю кодирования или потенциальные ошибки.

6. Форматировщик кода Prettier - это форматировщик кода, автоматически форматирующий код по установленным правилам,
улучшая читаемость и единообразие.

7. Конфигурация для линтера ESLint eslint-config-prettier - это конфигурация, отключающая правила линтера ESLint,
которые могут конфликтовать с форматировщиком кода Prettier.

8. Плагин для линтера ESLint eslint-plugin-prettier - это плагин, который интегрирует форматировщика кода Prettier в
процесс линтинга ESLint. Обеспечивает использование форматировщика кода Prettier как ESLint-правила, что позволяет
линтить код и форматировать его в одном процессе.

9. CLI nodemon - это CLI, который отслеживает изменения файлов в проекте и автоматически перезапускает приложение
Node.js при обнаружении изменений.

10. Генератор документации swagger-jsdoc - это инструмент для генерации документации API в формате Swagger на основе
комментариев JSDoc в коде. Помогает автоматически генерировать документацию API в стандартном формате Swagger.

11. Middleware swagger-ui-express - это middleware для backend‑фреймворка Express.js, который позволяет отображать
документацию Swagger в веб-интерфейсе, где разработчики могут просматривать и взаимодействовать с документацией API, что
позволяет тестировать API прямо из браузера.

12. Middleware-библиотека express-validator - это библиотека, предоставляющая middleware, который содержит набор функций
для backend‑фреймворка Express.js для валидации и санитизации данных из запросов.

13. Библиотека-драйвер MongoDB - это официальный драйвер для Node.js, предоставляющий низкоуровневый API для подключения
к серверам БД MongoDB, выполнения CRUD-операций, агрегаций, управления индексами и транзакциями.

14. Модуль Dotenv - это модуль, не зависящий ни от одного компонента, который загружает переменные окружения из файла
".env" в файл "process.env".

15. Библиотека хеширования bcrypt - это библиотека, которая предоставляет функции хеширования паролей с использованием
алгоритма bcrypt.

16. Библиотека хеширования @node-rs/argon2 - это библиотека, которая предоставляет функции хеширования паролей с
использованием алгоритма Argon2.

17. Библиотека jsonwebtoken - это библиотека для создания JWT-токенов.

18. Библиотека nodemailer - это библиотека для работы с протоколом SMTP.

19. Инструмент для тестирования MongoDB Memory Server - это инструмент, который позволяет создавать настоящую MongoDB в
RAM для тестирования. Автоматически скачивает бинарник MongoDB, запускает его в RAM и удаляет после тестов.

20. Библиотека date-fns - это библиотека для работы с датами, например, форматирование или вычисления.

21. CLI ts-node - это CLI, который позволяет запускать файлы TypeScript напрямую без компиляции в JavaScript.

22. Middleware-библиотека cookie-parser - это библиотека, предоставляющая middleware, который позволяет:
- Анализировать cookies.
- Заполнять объект "req.cookies" объектом, ключи которого являются именами cookies.
- Расширять объект "res" методом "cookie()" для упрощения установки cookies в ответе.
- Опционально включать поддержку подписанных cookies, передавая секретную строку, которая присваивает значение объекту
"req.secret", чтобы его могли использовать другие промежуточные обработчики.

23. Middleware cors - это middleware для backend‑фреймворкa Express.js, добавляющий CORS-заголовки, тем самым разрешая
кросс-доменные запросы из браузеров.

24. DI-фреймворк InversifyJS - это фреймворк в виде IoC-контейнера для внедрения зависимостей в TypeScript и JavaScript.
Помогает управлять созданием и связыванием классов. Работает в связке с полифиллом reflect-metadata.

25. Полифилл reflect-metadata - это полифилл для декораторов, добавляющий возможность сохранять метаданные о типах
параметров, необходим для работы DI-фреймворка InversifyJS и других DI-инструментов. Должен быть импортирован один раз в
точке входа в приложение.

26. ODM-библиотека Mongoose - это ODM-библиотека (Object Data Modelling), которая занимается преобразованием документов
из MongoDB в объекты JavaScript. Mongoose используется как обертка над драйвером MongoDB. Mongoose предоставляет более
удобный API для работы с Mongo БД. Mongoose позволяет определять схемы для MongoDB с целью контроля данных в Mongo БД.
Схемы это аналог типов из TypeScript.  Вместе со схемой нужно использовать модели - объекты, через которые идет
взаимодействие с Mongo БД. Не требует предварительной установки библиотеки-драйвера MongoDB.

27. Трансформер для Jest babel-jest - это трансформер, который сообщает тестовому фреймворку Jest, чтобы перед тем,
как запускать какой-то файл, нужно транспилировать его через транспилятор Babel. Используется, чтобы научить тестовый
фреймворк Jest понимать современный синтаксис JavaScript, например, ES-модули, который сам по себе он выполнить не
может.

28. Плагин для DI-фреймворка InversifyJS inversify-inject-decorators - это официальный плагин, который позволяет делать
"ленивую" подгрузку в DI-фреймворке InversifyJS. Выдает классу нужный сервис не сразу при старте, а только в момент
первого обращения к нему, что позволяет обойти циклические зависимости.

29. Плагин для линтера ESLint eslint-plugin-simple-import-sort - это плагин, позволяющий указывать ESLint-правила для
сортировки импортов. Требует донастройки файла "eslint.config.mjs".

30. Backend‑фреймворк NestJS - это backend‑фреймворк для Node.js, построенный поверх backend‑фреймворков Express.js или
Fastify. Использует TypeScript по умолчанию, архитектуру на основе модулей, DI, декораторы и строгую структурированную
организацию кода.

31. CLI Nest CLI - это CLI, который упрощает процесс создания, настройки и управления проектами на backend‑фреймворке
NestJS. С его помощью можно быстро генерировать модули, контроллеры, сервисы, запускать сервер разработки, тестировать
приложение и прочее.

32. Модуль backend‑фреймворка NestJS @nestjs/config - это официальный модуль для работы с конфигурацией приложения и
переменными окружения.

33. Модуль backend‑фреймворка NestJS @nestjs/mongoose - это официальный интеграционный модуль для работы с MongoDB через
Mongoose.

34. Библиотека class-validator - это библиотека для валидации входных данных через декораторы.

35. Библиотека class-transformer - это библиотека для преобразования обычных объектов в экземпляры классов и обратно,
предоставляя специальные декораторы для этого. В backend‑фреймворке NestJS эта библиотека работает в связке с пайпом
"ValidationPipe" для автоматической обработки Input DTO.

36. Модуль backend‑фреймворка NestJS @nestjs/swagger - это официальный модуль, который автоматически генерирует
документацию OpenAPI (Swagger) на основе контроллеров, DTO и декораторов. Чтобы не использовать декораторы Swagger,
можно настроить файл "nest-cli.json".

При работе с пакетами InversifyJS и reflect-metadata при помощи декоратора "@injectable()" помечается сущность, которая
может быть куда-то внедрена, а при помощи декоратора "@inject()" помечается то, что должно быть внедрено.

Чтобы обойти циклическую зависимость вместо декоратора "@inject()" можно использовать приватный геттер (паттерн Lazy
Loading, хотя обращение внутри класса к IoC-контейнеру является антипаттерном Service Locator):

private get postsService() {
    return container.get(PostsService);
  }

Альтернативно для решения проблемы с циклической зависимостью можно использовать пакет inversify-inject-decorators. Он
позволяет создавать декоратор "@lazyInject()", реализующий lazy loading, чтобы избежать создания экземпляра одного
класса внутри конструктора другого класса, что как раз и вызывает замкнутый круг зависимостей между двумя классами.
Поэтому декоратор "@lazyInject()" нужно указывать вне конструктора класса.

Чтобы Jest работал с InversifyJS нужно:
1. Установить Ядро компилятора Babel.
2. Установить пресет плагинов, который позволяет Babel транспилировать современный синтаксис JS в более старый.
3. Установить пакет, который говорит как Jest использовать Babel.
4. Добавить в файл "jest.config.ts", чтобы Jest заставлял Babel транспилировать код InversifyJS:
transformIgnorePatterns: ['node_modules(?!.*(?:inversify|@inversifyjs))'],
  transform: {
    '\\.tsx?$': 'ts-jest',
    '\\.js$': ['babel-jest', { presets: ['@babel/preset-env'] }],
  },

Это приходится делать, так как Jest по умолчанию игнорирует папку "node_modules", то есть считает, что весь код в этой
папке уже скомпилированным обычным JS и пытается просто выполнять его. Но InversifyJS выполнен в виде современного
ES-модуля (ESM), используя современный синтаксис JS, когда Jest ожидает старый формат (CommonJS). Поэтому настраиваем
так, чтобы Jest не игнорировал папку "node_modules", а Babel транспилировал код InversifyJS при запуске тестов.

Библиотека class-transformer позволяет:
1. Превращать сырой JSON из запроса в объект с методами класса при помощи метода "plainToInstance()".
2. Скрывать чувствительные данные при отправке ответа клиенту при помощи декоратора "@Exclude()".
3. Изменять значения на лету при помощи декоратора "@Transform()".
4. Переименовывать поля при сериализации или десериализации при помощи декоратора "@Expose({ name: 'user_id' })".
5. Указывать типы для вложенных объектов и массивов при помощи декоратора "@Type(() => Class)", чтобы они тоже
становились экземплярами нужных классов.
6. Управлять видимостью полей в разных контекстах (например, для разных типов пользователей), используя группы:
"@Expose({ groups: ['admin'] }) и @Exclude({ groups: ['user']) })".
7. Игнорировать лишние поля из входного объекта, которых нет в классе, используя опцию "excludeExtraneousValues: true".
8. Преобразовывать экземпляр обратно в обычный объект методами "instanceToPlain()" или "classToPlain()" (устаревший) для
отправки клиенту, применяя все правила.
